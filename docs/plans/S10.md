# S10 — the whole application in one `docker compose up`

**Goal.** `git clone && docker compose up` gives a working assistant at
`http://localhost:8000` — client, API, Postgres, schema migrated and the corpus
ingested — with **no Python, no Node, and no API key** on the machine. That
closes D-03 (*"Docker Compose to run the complete application"*), and it turns
the README S9e owes from a ten-step setup into two commands.

**Why this shape.** The evaluator's first five minutes decide how the rest is
read. Right now those five minutes are: install Python 3.12, make a venv,
`pip install -e .[dev]`, start Postgres, run Alembic, run ingest, start uvicorn,
`cd web`, `npm ci`, `npm run dev`, then open a *second* port. Every one of those
is a place to fail on someone else's machine, and none of them is the thing
being evaluated.

**A caveat stated up front, because this project's own rule says so.** D-03 is a
brief §3 **differential**, and the standing rule has been that differentials get
cut, never mandatory requirements. S9d (the live runs) and S9e (README,
architecture diagram, the register) are still outstanding, and the diagram is a
named §6 submission item. So S10 is only worth doing **because it makes S9e
cheaper rather than competing with it**: the README's "how to run it, verified
from a clean clone" becomes two commands, and the architecture diagram gets to
draw a deployment that exists. If the clock bites, **S9e ships first and S10 is
the thing that goes**.

## The one fact that decides the architecture

`web/src/api.ts:3` hardcodes `const BASE = '/api'`, and `web/vite.config.ts`
proxies `/api/*` to `http://localhost:8000/*` **with the prefix stripped**:

```ts
rewrite: (path) => path.replace(/^\/api/, ''),
```

So the client asks for `/api/healthz` and the backend serves `/healthz`. Any
container layout has to reproduce that rewrite, and the options differ mostly in
how much they cost:

| Option | Shape | Cost |
|---|---|---|
| **A. nginx** | `web` container serves `dist/` and proxies `/api` → `api:8000` | mirrors production, but two Dockerfiles, an `nginx.conf`, and a third service |
| **B. FastAPI serves both** | one `api` container: the existing app mounted at `/api`, the built client at `/` | one Dockerfile, one port, one origin |
| C. two ports | `api` on 8000, `web` on 5173 via `vite preview` | needs CORS, which S8 deliberately refused |

**Take B.** It is the smallest thing that works, it puts client and API on one
origin so the no-CORS decision stays true in production rather than only in dev,
and it gives the evaluator a single URL. C is disqualified outright — adding
`CORSMiddleware` to make a container demo work would undo S8's decision 3 for
convenience, in a codebase whose argument is exposure discipline.

### What B costs in application code: about fifteen lines

`create_app()` does **not** change. A thin wrapper mounts it:

```python
# app/main.py
def create_container_app() -> FastAPI:
    """Parent app: the API under /api, the built client at /.

    The client hardcodes BASE='/api' and the dev proxy strips that prefix, so
    mounting the API at /api reproduces the dev contract exactly — no route in
    app/api/routes.py moves, and every existing test keeps hitting /healthz and
    /conversations/... on the app object create_app() returns.
    """
    api = create_app()
    shell = FastAPI(title="InsurCo claims assistant")
    shell.mount("/api", api)                       # mount order matters:
    dist = Path(os.getenv("WEB_DIST", "web/dist")) # /api before /
    if dist.is_dir():
        shell.mount("/", StaticFiles(directory=dist, html=True), name="client")
    return shell
```

Three things make this safe rather than clever:

- **No route moves.** `routes.py` still declares `/healthz` and
  `/conversations/{id}/messages`. The prefix is a mount, so the 76 existing
  tests, which drive `create_app()` directly, are untouched.
- **A mounted ASGI sub-app keeps its own middleware and exception handlers**, so
  `TraceIdMiddleware` and the RFC 9457 handlers still run for API requests.
  `request.app.state` inside a mounted app resolves to the sub-app, which is
  where `state.llm`, `state.repo` and `state.pool` live.
- **`html=True` serves `index.html` at `/`**. The client has no client-side
  router, so there are no deep links to fall through to.

`uvicorn app.main:container_app` in the image; `app.main:app` stays the bare API
for anyone running it directly.

## The problem that actually breaks `docker compose up`

**A fresh volume has an empty database, and an empty database means every
question refuses.** Retrieval returns nothing, the sufficiency gate correctly
declines to answer, and the evaluator's first impression is an app that says
"não há base nas fontes" to everything. It would look like a broken product and
be a correct one.

So the API container's entrypoint is a four-step, **idempotent** boot:

```sh
#!/bin/sh
set -e
alembic upgrade head                                   # adopts an existing
                                                       # chunks table (S7a)
if [ "$(python -m scripts.chunk_count)" = "0" ]; then
  echo "empty index; ingesting data/corpus"
  python -m app.retrieval.ingest data/corpus --no-embed
else
  echo "index already populated; skipping ingest"
fi
exec uvicorn app.main:container_app --host 0.0.0.0 --port 8000
```

The count guard is what makes `docker compose up` safe to run twice: the second
boot migrates (a no-op), sees 220 chunks and skips straight to serving. Without
it, every restart re-parses thirteen PDFs.

`scripts/chunk_count.py` is four lines and exists so the shell does not have to
parse Python output. Ordering is handled by compose, not by a sleep:
`depends_on: db: condition: service_healthy`, against the healthcheck already in
the file.

### Why `--no-embed`, and why that is not a compromise

There is no embeddings cache in the repository — `git ls-files data/` returns 14
files, thirteen PDFs and `claims.db`. The 220 vectors in the current Postgres
were paid for in S3 and live only in that volume. A fresh clone therefore cannot
build the vector arm without an API key, and `EmbeddingCache` refuses to invent
one: a cache miss with no key raises rather than embedding zeros, which was S3's
deliberate choice.

**The keyless path is fully functional, not a degraded mode.** `--no-embed`
stores NULL vectors, `RETRIEVER_ARM=lexical` never reads them, and S3 measured
lexical recall@5 at **8/9 — the same as hybrid** on this corpus. With
`LLM_PROVIDER=fake` (already the default) the evaluator gets real retrieval over
the real thirteen documents and all seven interface states, for free.

The key is what unlocks Tier 2 and real answers, and it is opt-in:

```
LLM_PROVIDER=openai OPENAI_API_KEY=sk-... docker compose up
```

## Compose

```yaml
services:
  db:                      # unchanged from today
    image: pgvector/pgvector:pg17
    environment: { POSTGRES_USER: insurco, POSTGRES_PASSWORD: insurco, POSTGRES_DB: insurco }
    ports: ["5433:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U insurco -d insurco"]
      interval: 2s
      timeout: 5s
      retries: 20

  api:
    build: { context: ., dockerfile: Dockerfile }
    ports: ["8000:8000"]
    depends_on:
      db: { condition: service_healthy }
    environment:
      DATABASE_URL: postgresql://insurco:insurco@db:5432/insurco
      STORAGE: sql
      RETRIEVER: hybrid
      RETRIEVER_ARM: lexical          # keyless; see above
      LLM_PROVIDER: ${LLM_PROVIDER:-fake}
      OPENAI_API_KEY: ${OPENAI_API_KEY:-}
    healthcheck:
      test: ["CMD-SHELL", "python -c \"import urllib.request;urllib.request.urlopen('http://localhost:8000/api/healthz')\""]
      interval: 5s
      timeout: 5s
      retries: 12

volumes:
  pgdata:
```

`DATABASE_URL` is `db:5432`, not `localhost:5433` — the host port mapping is for
tools on the host, and inside the network it is the service name and the
container port. Getting this wrong is the classic first-run failure.

`${LLM_PROVIDER:-fake}` and `${OPENAI_API_KEY:-}` read from the host environment
or a `.env` beside the compose file. **`.env` is never `COPY`d into the image** —
`.dockerignore` excludes it, and the key arrives at runtime. Baking a secret into
a layer is exactly the exposure this codebase spends its effort avoiding.

## The Dockerfile — multi-stage, so Node never ships

```dockerfile
FROM node:20-slim AS client
WORKDIR /web
COPY web/package.json web/package-lock.json ./
RUN npm ci                       # cached unless the lockfile moves
COPY web/ ./
RUN npm run build                # tsc -b && vite build -> /web/dist

FROM python:3.12-slim AS runtime
WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends \
      libgl1 libglib2.0-0 && rm -rf /var/lib/apt/lists/*   # pymupdf
COPY pyproject.toml ./
COPY app/ ./app/
RUN pip install --no-cache-dir -e .
COPY alembic.ini ./
COPY scripts/ ./scripts/
COPY data/ ./data/               # the corpus; ingest needs it at boot
COPY --from=client /web/dist ./web/dist
COPY docker/entrypoint.sh /usr/local/bin/entrypoint
RUN chmod +x /usr/local/bin/entrypoint
EXPOSE 8000
ENTRYPOINT ["/usr/local/bin/entrypoint"]
```

Three details that will otherwise cost an hour each:

- **`libgl1` / `libglib2.0-0`.** `pymupdf` needs them and `python:*-slim` has
  neither. The failure is an ImportError at ingest, three minutes into a build.
- **`requires-python = ">=3.12"`**, so `python:3.12-slim`. `3.13-slim` is
  untested here and `pymupdf` wheels lag new minors.
- **`entrypoint.sh` must have LF endings.** This repository is developed on
  Windows and git is converting LF→CRLF on checkout; a CRLF shell script in a
  Linux image fails with `exec format error` or `no such file or directory`,
  which reads like a missing file rather than a line ending. `.gitattributes`
  pins `docker/entrypoint.sh text eol=lf`.

`.dockerignore` excludes `.venv/`, `web/node_modules/`, `.git/`, `.env`,
`evals/results/`, `docs/screenshots/` (the 1.2 MB GIF), and `**/__pycache__/`.

## Order of work — three commits

**S10a — the image, no compose changes.** `Dockerfile`, `.dockerignore`,
`docker/entrypoint.sh`, `scripts/chunk_count.py`, `.gitattributes`,
`create_container_app()`. Prove it standalone: `docker build -t insurco .` then
run it against the Postgres already on 5433. Existing suite must stay at
**76 passed, 10 deselected** — `create_app()` did not move.
→ `feat(docker): S10a multi-stage image serving the built client at /`

**S10b — the compose service.** The `api` service, healthcheck, `depends_on`.
Then the real test, and it is the only one that counts: **`docker compose down
-v` to destroy the volume, then `docker compose up` from nothing**, and confirm
the boot migrates, ingests thirteen documents, and serves. Anything that only
works on a warm volume has not been tested.
→ `feat(docker): S10b api service, one command from a cold volume`

**S10c — verified from a clean clone.** `git clone` into an empty directory,
`docker compose up`, open `http://localhost:8000`, ask gs-009, get the two
chips. Paste the transcript into `DECISIONS.md`. D-03 → `done`.
→ `docs: S10c compose verified from a clean clone, D-03 done`

## Gates

| Gate | How it is met |
|---|---|
| One command from a clean clone | `docker compose up` after `down -v`; the cold-volume run is the test, not the warm one |
| No Python, Node or API key needed | `LLM_PROVIDER=fake`, `--no-embed`, `RETRIEVER_ARM=lexical`; all seven states reachable |
| Client and API on one origin | API mounted at `/api`, client at `/`; no CORS middleware is added, so S8's decision 3 stays true |
| The 76 existing tests still pass | `create_app()` is untouched; only a wrapper is added |
| Idempotent boot | second `up` skips ingest via the chunk-count guard; `alembic upgrade head` is a no-op |
| No secret in the image | `.dockerignore` excludes `.env`; the key arrives as a runtime variable |
| The demo is still honest | `RETRIEVER_ARM=lexical` is documented as the keyless default with S3's 8/9 recall cited, not presented as equivalent to a configuration nobody ran |

## Out of scope for S10 — stated so it is not mistaken for an omission

**An nginx service.** Option A is the production shape and it is not this
project's deliverable. Named in `DECISIONS.md` as the thing to add when the
client needs a CDN or the API needs to scale separately.

**Committing an embeddings cache** so the vector arm works from a clone. It
costs an API call per chunk and a decision about committing generated vectors;
S3 measured lexical at parity on this corpus, so it buys nothing here.

**Publishing the image** to a registry. Nothing asks for it.

**A `web` container running Vite dev.** `npm run dev` with hot reload stays the
development path and the proxy stays in `vite.config.ts`. Containerising the dev
server would give two ways to run the same thing and a second place for the
proxy rule to drift.

**S9d and S9e.** Unchanged and still owed. If the clock forces a choice,
**S9e ships and S10 does not** — a differential does not compensate for a missing
submission item, and the architecture diagram is one.
